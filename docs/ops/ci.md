# CI của PR (check.yml)

CI chạy trên mọi PR vào `main` và mỗi push vào `main`. Luật dùng CI trong quy trình review / merge ở `CONTRIBUTING.md`; trang này mô tả CI làm gì. Lệnh chạy bot ở máy: `docs/ops/chay-local.md`. Release / Promote sau merge: `docs/ops/trien-khai.md`.

Ba job chính (`changes`, `check-build`, `bot-ram`):

- `check-build` (ubuntu + Windows): `npm ci` (server + client, cài đúng lockfile), bài âm thanh, `npm run check`, `npm run build`, `npm run budget` (ngân sách dung lượng, dưới).
- `changes` (job đầu tiên, `tools/ci/changes.sh`): chọn **mức bot** theo file PR đổi so với base, in mức và lý do ra Summary. `full` khi chạm `server/**`, `shared/**` (trừ ảnh / âm thanh / manifest sprite), `client/src/net.ts`, `predict.ts`, `hud.ts`, `autoPanel.ts`, `main.ts`, `scenes/GameScene.ts`, `client/scripts/**`, `tools/**`, `.github/**`, `package*.json`, `server/sql/**`, file bản đồ `shared/assets/<bản đồ>[.v2].json`, hoặc file không nhận ra (không chắc thì full); `smoke` khi chỉ đổi mã giao diện client còn lại (`client/src/**`, CSS, html); `skip` khi chỉ đổi ảnh / âm thanh / manifest sprite / `*.md` / `docs/**` / `art/**`. **Push vào `main`** cũng chọn mức, so với commit trước (`github.event.before`), quy tắc chặt hơn PR (`PUSH=1` trong `changes.sh`): chỉ `art/**`, `docs/**`, `*.md`, `.claude/**` mới `skip`; mọi thứ khác (kể cả ảnh / âm thanh ở `shared/assets/**`, vì vào image) và khi không so được thì `full`. Nhãn PR ép mức: `ci:full` → full, `ci:bot-khoi` → ít nhất smoke; nhãn được đọc lúc job `changes` chạy: gắn nhãn rồi bấm Re-run (hoặc push) là có hiệu lực, đổi nhãn không tự tạo lượt CI mới. `check-build` luôn chạy đủ ở mọi mức.
- `bot-ram` (ubuntu): ở mức `skip` không chạy bot, báo success; ở mức `smoke` job `bot-smoke` chạy `test:predict`, `test:charbag` và một lượt bot khói (`BOT_PART=smoke`: phần chung đăng nhập / bản đồ / di chuyển / đánh quái / túi / nhân vật cùng vài bài nhẹ khai báo ở `SMOKE` trong `client/scripts/bot-test.mjs`, ~3 phút); ở mức `full` bot trên server mới bật `GAME_TEST=1` chế độ RAM, chia 6 job song song `bot-ram (nhóm 1|2|3|4|5|6)` theo `BOT_PART` (bot đầy đủ ~35 phút, mỗi nhóm ~7–8 phút; đích ≤ ~8 phút, trần bước bot 12 phút, #684; phần nào thuộc nhóm nào khai báo một chỗ ở `INLINE` / `STANDALONE` đầu phần chia nhóm trong `client/scripts/bot-test.mjs`, bài mới tự tạo bot thì thêm vào `STANDALONE` và gắn nhóm đang nhẹ theo dòng `⏱` thời gian từng phần mà mỗi nhóm in ở annotation; bước bot quá 12 phút thì coi là treo); nhóm 1 chạy thêm `test:predict`, `test:ratelimit`, `test:accounts` và lượt nhiều kênh (`CHANNEL_MAX=2`). Job `bot-ram` gộp kết quả 6 nhóm (annotation phân biệt có nhóm trượt với bị hủy / hết giờ). Mỗi lượt qua `tools/ci/bot-run.sh` (chạy được ở máy Linux / macOS: `BOT_PART=2 bash tools/ci/bot-run.sh nhom-2`). Bot trượt thì in log server, log đầy đủ ở artifact `bot-logs-<nhóm>` của lượt chạy.
- `flow-browser` (ubuntu, mức `smoke` và `full`, #713): `npm run test:flow-browser --prefix client` mở Chromium (Playwright) trên server `GAME_TEST=1` RAM phục vụ bản build: landing `/` → "Vào chơi" → đăng ký bằng mật khẩu → tạo nhân vật LPC → Lễ thức tỉnh (mọi thẻ võ hồn có khung riêng, không chồng nhau, click chuột thật được) → vào game (HUD hiện, giữ phím D thì đi được) → không `pageerror` / `console.error` ngoài danh sách cho phép (`/private/*` 404). ~2 phút gồm build client; trượt thì ảnh ở artifact `flow-browser-<sha>`. Ở máy: `FLOW_CHANNEL=chrome npm run test:flow-browser --prefix client` (dùng Chrome cài sẵn, luôn `--mute-audio`; `FLOW_BUILD=1` build lại client). Đăng nhập Google chưa nằm trong bài (cần nút Google thật). Cài Chrome (cả `flow-browser` và `nameplate-preview`, #933): `actions/cache` cho `~/.cache/ms-playwright` theo phiên bản `playwright` trong `client/package-lock.json`; trúng cache chỉ `install-deps`, trượt thì `install --with-deps`; bước cài có `timeout-minutes: 8`, job 20.

## Vai trò
- CI **chỉ để tham khảo**, không là status check bắt buộc trong bảo vệ nhánh `main` (Q29 ở `docs/quyet-dinh.md`; không đổi ruleset). CI đỏ thì đọc log: lỗi do PR thì sửa, bot chập chờn thì xử lý theo skill `bot-flakiness`, lỗi hạ tầng (GitHub Actions, mạng) thì ghi lý do trong PR.

## Đọc kết quả
- **Reviewer dùng kết quả CI cho bot RAM**, không tự chạy lại bot RAM: `gh pr checks <PR>` (`bot-ram` và 6 nhóm của đúng head đang review), `gh run view <run-id>` in annotation số dòng ✓ / ✗ / ⚠ của từng nhóm và các dòng ✗ (bảng đầy đủ kèm dòng ⚠ ở trang lượt chạy, mục Summary), đỏ thì `gh run view <run-id> --log-failed`. Head chưa có lượt `bot-ram` xong (đang chạy, bị hủy) thì chờ lượt mới. Lượt **PostgreSQL** CI chưa có: PR đổi SQL / `db.ts` thì reviewer vẫn tự chạy bằng `npm run bot:local -- --only <nhóm> --pg` (`CONTRIBUTING.md` mục Xin review).

## Ngân sách dung lượng bản build client (#743)
`tools/bundle-budget.mjs` (`npm run budget`, chạy sau `npm run build` trong `check-build`) đo `client/dist` theo năm nhóm: JS landing, JS game (không Phaser), JS Phaser, CSS, ảnh landing (`ui/landing`). Ngưỡng mỗi nhóm = mốc × `heso` (1,1, tức mốc + 10 %), mốc và hệ số ở `tools/bundle-budget.json`. Vượt thì job đỏ và in bảng từng nhóm. Không gắn vào `npm run check` vì check không build.
Tăng dung lượng có chủ đích (thêm tính năng, ảnh landing mới): build lại, chạy `node tools/bundle-budget.mjs --update` để ghi mốc mới, commit `bundle-budget.json` cùng PR và nêu lý do trong mô tả PR. Giảm dung lượng nhiều (như #716) thì cũng nên hạ mốc để ngưỡng không lỏng.

## CI nhẹ cho tờ hồn thú (#866)
Job `beast-sheet-check` (chỉ PR, ubuntu, không `npm ci`, không Chrome / server / bot; chạy ở mọi mức bot kể cả `skip`, nên không phá cơ chế art-only #846 / #848). PR đổi `art/src/beast-anim/**` hoặc `tools/assets/beast-sheet-*` thì `tools/assets/beast-sheet-ci.mjs` chạy `beast:check` cho loài có **tờ `toA..toE.png` đổi** (đổi NGUON.md / prompt không kích hoạt), ghi bảng tóm tắt vào job summary và artifact `beast-check-<sha>` (JSON, markdown, tờ liên hệ có nhãn; tối đa 12 loài có ảnh). **Chặn** (job đỏ) chỉ khi: cỡ ngoài tập cho phép, nền ngoài dung sai, thiếu khung / hình dính, không dò được lưới; mọi phát hiện khác (cỡ thân, chân lệch, khung chết, hurt = idle, `se` ≈ `e`…) chỉ là cảnh báo trong bảng. PR chỉ đổi công cụ thì kiểm mọi loài để báo cáo, không chặn (dữ liệu cũ còn loài chưa đạt). Hướng mặt và hurt ngửa bụng vẫn do mắt người xem trang xoay vòng hướng (`docs/art/hon-thu-hoat-anh.md`). CI không là status check bắt buộc.

PR đổi `art/src/ui-kit/**` hoặc `tools/assets/ui-sheet-*` / `ui-kit-*` thì `tools/assets/ui-sheet-ci.mjs` chạy `ui:check` cho **tờ PNG đổi** (`toF.png`, `N-2.png`, `BOARD.png`… dưới `art/src/ui-kit/`; đổi prompt / NGUON không kích hoạt), ghi bảng tóm tắt vào job summary và artifact `ui-check-<sha>`: JSON, markdown, tờ liên hệ có nhãn (tối đa 12 tờ) và `ui-kit-preview/index.html` (trang bộ component dựng từ tờ không chặn; PR đổi công cụ hoặc spec thì thêm tờ giả lập C2 / UI-5). **Chặn** (job đỏ) chỉ khi: cỡ / tỉ lệ ngoài tập cho phép, nền ngoài dung sai, thiếu mảnh / mảnh dính / thiếu trạng thái, không dò được dải; mọi phát hiện khác (viền hồng, cạnh không phẳng, quá nhiều màu, chữ lạc…) chỉ là cảnh báo trong bảng. PR chỉ đổi công cụ / `ui-kit.json` / `lessons.md` thì kiểm mọi tờ đang có để báo cáo, không chặn. CI không là status check bắt buộc.

## Push chỉ đổi art / docs (#846)
Merge PR ảnh gốc (`art/**`) hay tài liệu không cần cả bộ CI nặng trên `main`. Mức `skip` ở push: không chạy bot-ram 6 nhóm, `bot-smoke`, `flow-browser`, `nameplate-preview`, `presence-redis`, `docker-build`; `check-build` chỉ ubuntu và bỏ `build` + `budget`, vẫn chạy `npm run check` (docs-check, CREDITS / sprite), bài âm thanh và `test-unit` (gồm `test:assets`). Job bị bỏ qua báo `skipped`, riêng `bot-ram` báo `success`; CI không là status check bắt buộc (Q29) nên không kẹt `pending`.

**Release:** job `gate` ở `release.yml` so commit với commit của lượt Release gần nhất đã thành công (dựng xong hoặc bỏ qua hợp lệ; không lấy lượt CI trước vì CI đỏ / Release trượt thì mã đó chưa vào image), cả khoảng nên rebase-merge nhiều commit vẫn đúng; không tìm được mốc hoặc mốc không là tổ tiên thì dựng; không đổi `server/**`, `client/**`, `shared/**`, `Dockerfile`, `.dockerignore`, `package*.json` thì không dựng image, chỉ đặt trạng thái `release/image` = success ("bỏ qua: commit không đổi image"). Có đổi một trong đó, chạy tay (`workflow_dispatch`), hoặc không so được thì dựng như thường. `concurrency: release` nằm ở job `release` (không phải cả workflow) để lượt bị bỏ qua không thay thế lượt dựng đang chờ. Đổi quy tắc image thì sửa cả Dockerfile lẫn regex ở `gate`.
