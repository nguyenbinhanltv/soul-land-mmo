# CI của PR (check.yml)

CI chạy trên mọi PR vào `main` và mỗi push vào `main`. Luật dùng CI trong quy trình review / merge ở `CONTRIBUTING.md`; trang này mô tả CI làm gì. Lệnh chạy bot ở máy: `docs/ops/chay-local.md`. Release / Promote sau merge: `docs/ops/trien-khai.md`.

Các job chính (`changes`, `check-build`, `assets-check`, `bot-ram`):

- `check-build` (ubuntu + Windows; **bỏ ở mức `assets`**, thay bằng `assets-check`): `npm ci` (server + client, cài đúng lockfile), bài âm thanh, `npm run check`, `npm run build`, `npm run budget` (ngân sách dung lượng, dưới).
- `npm run check` có thêm `tools/ci/check-css-tokens.mjs` (đợt 5c): màu `#hex` / `rgba()` thô trong `client/src/ui2*.css` không được vượt trần (xem `docs/art/ui-kit.md`).
- `assets-check` (ubuntu, chỉ ở mức `assets`, #1118): không `npm ci`, không build / Chrome / server / bot, đích ≤ 3 phút. Chạy `validate.mjs`, `quality.mjs --check`, `credits.mjs --check`, `normal-quant.mjs --check`, `lpc-parts.mjs --check`, `iso-atlas.mjs --check`, `maps/quet-chan.mjs`, `ci/check-private-assets.mjs` (chặn gói riêng / giấy phép lọt repo công khai), `docs-check.mjs`, kiểm `shared/assets/sprites/manifest.json` và `shared/assets/credits/credits.json` đọc được, và bài `beastanim-test.mjs` (chọn khung hoạt ảnh, chạy thẳng bằng Node). Các bài của `npm run check` **không** đưa vào vì không kiểm file mức `assets` hoặc cần deps nặng: `tools/check.mjs` (tsc, cần `node_modules`), `audio/compose/validate.mjs`, `validate-sfx.mjs` (âm thanh), `maps/build.mjs --check` (bản đồ), `landing-gen.mjs --check`, `check-css-class-owner`, `check-global-maps` (mã). Không có `npm run build` / `budget` ở mức này: PR thêm ảnh lớn không bị chặn ngân sách bundle ở PR (chỉ lộ ở lượt hằng ngày); cần chắc thì gắn `ci:full`. Công cụ mới cho PR ảnh phải chỉ dùng `node:*` (cần thư viện thì job không còn "nhẹ").
- `changes` (job đầu tiên, `tools/ci/changes.sh`): chọn **mức** theo file PR đổi so với base, in mức và lý do ra Summary. Bốn mức: `assets` < `skip` < `smoke` < `full`. `assets` (#1118): mọi file đổi nằm trong `art/**`, `shared/assets/sprites/**` (ảnh `.png` / `.webp`, `*_n.png`, `manifest.json`), `shared/assets/credits/credits.json`, `docs/**`, `*.md`, `.claude/**` (trừ `.md` dưới `.github/`, `tools/ci/`: đổi CI luôn full); chỉ chạy `assets-check`, `test-unit`, `beast-sheet-check`, `ui-sheet-check`, `changes`; `check-build` (cả hai hệ điều hành), `nameplate-preview`, `flow-browser`, `bot-ram`, `bot-smoke`, `presence-redis`, `docker-build` báo `skipped` (xanh; `bot-ram` báo `success`). `full` khi chạm `server/**`, `shared/**` (trừ ảnh / âm thanh / manifest sprite), `client/src/net.ts`, `predict.ts`, `hud.ts`, `autoPanel.ts`, `main.ts`, `scenes/GameScene.ts`, `client/scripts/**`, `tools/**`, `.github/**`, `package*.json`, `server/sql/**`, file bản đồ `shared/assets/<bản đồ>[.v2].json`, hoặc file không nhận ra (không chắc thì full); `smoke` khi chỉ đổi mã giao diện client còn lại (`client/src/**`, CSS, html); `skip` (chỉ PR) khi file còn lại chỉ là âm thanh / manifest âm thanh / `iso/tiles.json` / ảnh ngoài `sprites/` (vẫn chạy `check-build`, không bot). **Push vào `main`** cũng chọn mức, so với commit của **lượt CI `main` gần nhất có conclusion success** (tìm qua API, phải là tổ tiên; không có thì dự phòng `github.event.before`), quy tắc chặt hơn PR (`PUSH=1` trong `changes.sh`): chỉ file thuần ảnh / tài liệu của mức `assets` mới ra `assets`; mọi thứ khác (kể cả âm thanh, file bản đồ ở `shared/assets/**`) và khi không so được thì `full`. Nhãn PR ép mức: `ci:full` → full, `ci:bot-khoi` → ít nhất smoke; nhãn được đọc lúc job `changes` chạy: gắn nhãn rồi bấm Re-run (hoặc push) là có hiệu lực, đổi nhãn không tự tạo lượt CI mới. `check-build` luôn chạy đủ ở mọi mức trừ `assets`. Thử quy tắc: `bash tools/ci/changes.test.sh`. **Lượt hằng ngày (#1118):** `check.yml` có `schedule` (03:00 giờ Việt Nam) và `workflow_dispatch`, ép `full` (`FORCE_FULL`) để bắt lỗi tích hợp mà merge PR ảnh không phải trả giá; nhóm concurrency riêng (`ci-CI-hang-ngay`) nên không hủy / bị hủy bởi push; không là lượt `push` nên không kích Release và không làm mốc so sánh của push main.
- `bot-ram` (ubuntu): ở mức `skip` không chạy bot, báo success; ở mức `smoke` job `bot-smoke` chạy `test:predict`, `test:charbag` và một lượt bot khói (`BOT_PART=smoke`: phần chung đăng nhập / bản đồ / di chuyển / đánh quái / túi / nhân vật cùng vài bài nhẹ khai báo ở `SMOKE` trong `client/scripts/bot-test.mjs`, ~3 phút); ở mức `full` bot trên server mới bật `GAME_TEST=1` chế độ RAM, chia 6 job song song `bot-ram (nhóm 1|2|3|4|5|6)` theo `BOT_PART` (bot đầy đủ ~35 phút, mỗi nhóm ~7–8 phút; đích ≤ ~8 phút, trần bước bot 12 phút, #684; phần nào thuộc nhóm nào khai báo một chỗ ở `INLINE` / `STANDALONE` đầu phần chia nhóm trong `client/scripts/bot-test.mjs`, bài mới tự tạo bot thì thêm vào `STANDALONE` và gắn nhóm đang nhẹ theo dòng `⏱` thời gian từng phần mà mỗi nhóm in ở annotation; bước bot quá 12 phút thì coi là treo); nhóm 1 chạy thêm `test:predict`, `test:ratelimit`, `test:accounts` và lượt nhiều kênh (`CHANNEL_MAX=2`). Job `bot-ram` gộp kết quả 6 nhóm (annotation phân biệt có nhóm trượt với bị hủy / hết giờ). Mỗi lượt qua `tools/ci/bot-run.sh` (chạy được ở máy Linux / macOS: `BOT_PART=2 bash tools/ci/bot-run.sh nhom-2`). Bot trượt thì in log server, log đầy đủ ở artifact `bot-logs-<nhóm>` của lượt chạy. `bot-run.sh` và `bot-image.sh` đặt `BOT_STRICT_HOOK=1`: bài bị bỏ qua **vì thiếu hook test** (hook hỏng, mất `GAME_TEST`) ghi ✗ "bài bị bỏ qua vì thiếu hook" nên bot thoát 1, không để cả nhóm bài im lặng không chạy mà vẫn xanh (#958). Bài mới cần hook phải dùng `needHookSkip(msg)` (`client/scripts/bot/lib.mjs`), không tự `console.log("⚠ …")`; ⚠ thường chỉ cho bỏ qua vì dữ liệu / hình học. Chạy local không đặt biến thì vẫn chỉ ⚠.

## Hai làn: CI đầy đủ ở main, mức nhẹ ở PR (28/10)
Theo quy trình hai làn (`CONTRIBUTING.md` mục Hai làn): **CI đầy đủ chạy trên `main`** (mỗi push, mức theo `changes.sh` như trên) **và lượt hằng ngày** (`full`). Ở PR chỉ cần mức của `changes`: làn nhanh (art / docs / assets) là mức `assets` (`assets-check`), hoặc không cần PR mà gộp theo lô thẳng vào `main`; làn code merge khi mức `changes` xanh (`smoke` / `full`). Không chờ AO review làm điều kiện merge. Sau mỗi lô đẩy `main` xem lượt CI `main`; đỏ thì mở issue và sửa ngay. Workflow và hook không đổi.

## Vai trò
- CI **chỉ để tham khảo**, không là status check bắt buộc trong bảo vệ nhánh `main` (Q29 ở `docs/quyet-dinh.md`; không đổi ruleset). CI đỏ thì đọc log: lỗi do PR thì sửa, bot chập chờn thì xử lý theo skill `bot-flakiness`, lỗi hạ tầng (GitHub Actions, mạng) thì ghi lý do trong PR.

## Ngân sách dung lượng bản build client (#743)
`tools/bundle-budget.mjs` (`npm run budget`, chạy sau `npm run build` trong `check-build`) đo `client/dist` theo năm nhóm: JS landing, JS game (không Phaser), JS Phaser, CSS, ảnh landing (`ui/landing`). Ngưỡng mỗi nhóm = mốc × `heso` (1,1, tức mốc + 10 %), mốc và hệ số ở `tools/bundle-budget.json`. Vượt thì job đỏ và in bảng từng nhóm. Không gắn vào `npm run check` vì check không build.
Tăng dung lượng có chủ đích (thêm tính năng, ảnh landing mới): build lại, chạy `node tools/bundle-budget.mjs --update` để ghi mốc mới, commit `bundle-budget.json` cùng PR và nêu lý do trong mô tả PR. Giảm dung lượng nhiều (như #716) thì cũng nên hạ mốc để ngưỡng không lỏng.

## CI nhẹ cho tờ hồn thú (#866)
Job `beast-sheet-check` (chỉ PR, ubuntu, không `npm ci`, không Chrome / server / bot; chạy ở mọi mức kể cả `assets` / `skip`, nên không phá cơ chế art-only #846 / #848). PR đổi `art/src/beast-anim/**` hoặc `tools/assets/beast-sheet-*` thì `tools/assets/beast-sheet-ci.mjs` chạy `beast:check` cho loài có **tờ `toA..toE.png` đổi** (đổi NGUON.md / prompt không kích hoạt), ghi bảng tóm tắt vào job summary và artifact `beast-check-<sha>` (JSON, markdown, tờ liên hệ có nhãn; tối đa 12 loài có ảnh). **Chặn** (job đỏ) chỉ khi: cỡ ngoài tập cho phép, nền ngoài dung sai, thiếu khung / hình dính, không dò được lưới; mọi phát hiện khác (cỡ thân, chân lệch, khung chết, hurt = idle, `se` ≈ `e`…) chỉ là cảnh báo trong bảng. PR chỉ đổi công cụ thì kiểm mọi loài để báo cáo, không chặn (dữ liệu cũ còn loài chưa đạt). Hướng mặt và hurt ngửa bụng vẫn do mắt người xem trang xoay vòng hướng (`docs/art/hon-thu-hoat-anh.md`). CI không là status check bắt buộc. **Ở máy (#971):** cùng lệnh có chế độ `--local` (`beast-sheet-ci.mjs` / `ui-sheet-ci.mjs`, tự lấy file đổi từ git, in `LỖI:` + cách sửa); `npm run check` chạy cả hai trên file đổi so với `origin/main` + đang sửa, hook `pre-commit` chạy trên file đã stage khi đổi tờ `art/src/beast-anim` / `art/src/ui-kit` hoặc công cụ kiểm tờ.

## CI nhẹ cho tờ UI Kit (#880)
Job `ui-sheet-check` (chỉ PR, ubuntu, không `npm ci`, không Chrome / server / bot; chạy ở mọi mức kể cả `assets` / `skip`, nên giữ nguyên cơ chế art-only #846 / #848: `art/**` giờ là mức `assets`). PR đổi `art/src/ui-kit/**` hoặc `tools/assets/ui-sheet-*` / `ui-kit-*` thì `tools/assets/ui-sheet-ci.mjs` chạy `ui:check` cho **tờ PNG đổi** (`toF.png`, `N-2.png`, `BOARD.png`… dưới `art/src/ui-kit/`; đổi prompt / NGUON không kích hoạt), ghi bảng tóm tắt vào job summary và artifact `ui-check-<sha>`: JSON, markdown, tờ liên hệ có nhãn (tối đa 12 tờ) và `ui-kit-preview/index.html` (trang bộ component dựng từ tờ không chặn; PR đổi công cụ hoặc spec thì thêm tờ giả lập C2 / UI-5). **Chặn** (job đỏ) chỉ khi: cỡ / tỉ lệ ngoài tập cho phép, nền ngoài dung sai, thiếu mảnh / mảnh dính / thiếu trạng thái, không dò được dải; mọi phát hiện khác (viền hồng, cạnh không phẳng, quá nhiều màu, chữ lạc…) chỉ là cảnh báo trong bảng. PR chỉ đổi công cụ / `ui-kit.json` / `lessons.md` thì kiểm mọi tờ đang có để báo cáo, không chặn. CI không là status check bắt buộc.

## Push chỉ đổi ảnh / docs (#846, #1118)
Merge PR ảnh (`art/**`, nhập sprite `shared/assets/sprites/**`, `credits.json`) hay tài liệu không cần cả bộ CI nặng trên `main`. Mức `assets` ở push (cùng tập file với PR, không có mức `skip` ở push): chỉ chạy `assets-check` và `test-unit`; không `check-build` (cả Windows), bot-ram 6 nhóm, `bot-smoke`, `flow-browser`, `nameplate-preview`, `presence-redis`, `docker-build`. Job bị bỏ qua báo `skipped`, riêng `bot-ram` báo `success`; CI không là status check bắt buộc (Q29) nên không kẹt `pending`. Lượt `assets` vẫn kết thúc `success`. Bù lại có lượt `full` hằng ngày (trên) bắt lỗi tích hợp; cần chắc ngay thì gắn `ci:full` ở PR hoặc chạy tay `CI` trên `main`.

**Concurrency của CI (#1079):** `check.yml` đặt `group: ci-<workflow>-<số PR hoặc ref>` và `cancel-in-progress: true`: commit mới trên cùng nhánh PR hủy lượt CI cũ của PR đó; push mới lên `main` hủy lượt CI cũ của `main`; PR khác nhau (và PR với `main`) nằm nhóm khác nên không hủy nhau. Cache / matrix (`bot-ram` 6 nhóm, cache Chrome Playwright, `playwright-cache.yml`, `beast-status.yml`) không đổi: chúng nằm trong cùng lượt CI nên bị hủy cùng lượt, còn workflow khác có group riêng. Lượt CI bị hủy có conclusion `cancelled`: `release.yml` (`gate` chỉ chạy khi `conclusion == success`) bỏ qua, không chạy Release và không đỏ; lượt cuối của `main` vẫn Release bình thường, và `gate` so với lượt Release thành công trước nên image gồm cả các commit bị hủy. Vì mốc là lượt thành công gần nhất, lượt bị hủy không làm lượt sau ra `skip`: merge A (đổi `server/**`) rồi B (chỉ `docs/**`) mà lượt A bị hủy thì lượt B vẫn so với mốc trước A, thấy `server/**` nên chạy `full`. Rủi ro chấp nhận: commit giữa chuỗi merge nhanh vào `main` không có lượt CI riêng (lượt sau quét cả khoảng từ lượt thành công gần nhất tới nó, và mỗi PR đã có CI riêng trước khi merge); API lỗi thì dự phòng `before` có thể bỏ sót một lần.

**Release:** merge PR ảnh vẫn dựng image: `gate` chỉ nhìn file đổi, không nhìn mức CI, mà `shared/assets/sprites/**` nằm trong `shared/` nên khớp regex image. Job `gate` ở `release.yml` so commit với commit của lượt Release gần nhất đã thành công (dựng xong hoặc bỏ qua hợp lệ; không lấy lượt CI trước vì CI đỏ / Release trượt thì mã đó chưa vào image), cả khoảng nên rebase-merge nhiều commit vẫn đúng; không tìm được mốc hoặc mốc không là tổ tiên thì dựng; không đổi `server/**`, `client/**`, `shared/**`, `Dockerfile`, `.dockerignore`, `package*.json` thì không dựng image, chỉ đặt trạng thái `release/image` = success ("bỏ qua: commit không đổi image"). Có đổi một trong đó, chạy tay (`workflow_dispatch`), hoặc không so được thì dựng như thường. `concurrency: release` nằm ở job `release` (không phải cả workflow) để lượt bị bỏ qua không thay thế lượt dựng đang chờ. Đổi quy tắc image thì sửa cả Dockerfile lẫn regex ở `gate`.
