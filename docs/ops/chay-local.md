# Chạy local: lệnh, bot, PostgreSQL, tài khoản test

Lệnh hằng ngày cho người và agent. Luật code ngắn gọn ở `CLAUDE.md`; quy trình nhận việc / PR ở `CONTRIBUTING.md`. Trang này là nơi chi tiết.

## Lệnh
```bash
npm run install:all            # cài thư viện server + client (clone mới)
npm run hooks                  # bật git pre-commit hook (.githooks/, typecheck file đã stage) – một lần
npm run check                  # typecheck server + client, validate sprite, kiểm tiles.json, docs-check – bắt buộc sau mỗi thay đổi
npm run build                  # build client (tsc + vite)
npm run dev:server             # server http://localhost:2567 (không có DATABASE_URL thì lưu RAM)
npm run dev:client             # trang giới thiệu http://localhost:5173, game http://localhost:5173/choi/ (landing ở "/", #656)
npm run bot:local -- --only <nhóm> [--pg]   # bot ở máy: tự bật server GAME_TEST=1 cổng trống, chạy một nhóm, tự dọn
npm run bot --prefix client    # bot thô, chạy khi server đang bật (SERVER_URL=… nếu khác cổng); agent dùng bot:local
```

## Bot ở máy
- **Agent chạy bot ở máy bằng `npm run bot:local`** (`tools/bot-local.mjs`), **không** tự bật server rời hay embedded-postgres riêng: công cụ build server một lần (esbuild, cache theo hash nguồn) rồi chạy `node` với trần heap 768 MB, `GAME_TEST=1`, cổng trống, state sạch; chạy đúng một nhóm (`--only <nhóm>` BOT_ONLY, `--part 1..6` BOT_PART, `--channels` lượt nhiều kênh `CHANNEL_MAX=2`, `--fatal [--pg]` lỗi nghiêm trọng ngoài phòng làm server lưu rồi thoát (đổi `index.ts` / cách tắt server thì chạy); `--help` liệt kê nhóm); chỉ tắt tiến trình con của mình (kể cả Ctrl+C / lỗi) và in RAM đỉnh. **Tối đa 2 lượt bot cùng lúc trên cả máy** (khoá ở `%TEMP%/soul-bot-slots`), lượt thứ 3 tự chờ. Bot đầy đủ (`--full`, ~35 phút) để job CI `bot-ram` chạy. Với `GAME_TEST=1`, lịch boss đứng yên ở 12:00 giờ Việt Nam trừ khi đặt `--env BOSS_CLOCK=HH:MM` (hoặc `real`).
- Đổi presence / trạng thái dùng chung nhiều tiến trình: thêm `--procs 2 --pg` (công cụ tự bật `redis-server` riêng mỗi lượt ở cổng trống, binary ở `BOT_REDIS_BIN` hoặc PATH, chỉ tắt đúng PID đó; **không** cho hai lượt dùng chung một Redis vì pub/sub và phòng của Colyseus không theo `REDIS_PREFIX`; `REDIS_URL` của shell bị bỏ, tự bật Redis thì mỗi lượt một cổng qua `--env REDIS_URL=…`); `npm run test:presence-kill --prefix server` thử kill PID / TTL với Redis thật.
- **Bài đo đường đi `pathflow`** (L1 #1659): `npm run bot:local -- --only pathflow` (`client/scripts/bot/pathflow.mjs`; `PF_MAPS`, `PF_MIN_TILES`; không thuộc bot đầy đủ / CI, ~9 phút): bot đi từ trại hồi sinh tới từng truyền tống trận / cổng / tinh anh / hang của Ngoại vi, Nội địa, Lạc Nhật bằng `findLongPath` + `input`, in giây, số lần đứng yên > 1 giây, số lần tính lại đường, kẹt thật và dòng `PATHFLOW_JSON` để so baseline trước / sau khi sửa bản đồ.
- Bot cần server bật `GAME_TEST=1` (hook `test`; thiếu thì bot báo bỏ qua phần lớn kiểm tra) và **server mới bật**. Người chạy tay (gỡ lỗi kèm trình duyệt): `GAME_TEST=1 PORT=2600 npm run dev:server` rồi `SERVER_URL=http://localhost:2600 npm run bot --prefix client`.
- Bot không assert mọi thứ: đọc output (dòng ✗ là lỗi, ⚠ là bị bỏ qua; bài cần hook test thì bỏ qua qua `needHookSkip` ở `bot/lib.mjs`: ⚠ ở máy, ✗ khi `BOT_STRICT_HOOK=1` như CI) và log server. Luồng mới thì viết ở `client/scripts/bot/<tên>.mjs` rồi đăng ký ở `bot-test.mjs`.

**Cấu trúc bài bot** (`client/scripts`, #703): `bot-test.mjs` chỉ còn bộ chạy + bảng nhóm (`INLINE`, `STANDALONE`, `BOT_PART`, các nhánh `BOT_ONLY`). Phần chung và luồng A / B nằm ở `bot/ab.mjs` (`abFlow({ inPart })`: trả `{ HOOK, tiled, st, blocked, vil }` cho bot C và các bài `STANDALONE` cần `vil` / `blocked`). `bot/lib.mjs` giữ tiện ích dùng chung (`API`, `ok`, `failCount()`, `bot`, `enter`, `test`, `goTo`…). Mỗi nhóm độc lập là một `bot/<nhóm>.mjs` xuất `async function <nhóm>Test()`. Các khối `INLINE` dùng chung biến của luồng A / B là hàm nhận một đối tượng ngữ cảnh `ctx` (những biến luồng đó mà khối cần, ghi lại ở chỗ gọi): `bot/ab1.mjs` (`ab1Block1..3`, nhóm 1), `bot/ab2.mjs` (`ab2Block1..9`, nhóm 2), `bot/botC.mjs` (`botCFlow` + NPC / cổng / boss thế giới, nhóm 3; `ctx.world` ứng với `BOT_ONLY=world`). Khối mới cần biến của luồng thì nhận qua `ctx`, đừng dùng biến toàn cục. Bài độc lập còn lại cũng nằm ở `bot/<nhóm>.mjs` (`offline`, `mapview`, `issue121`, `party`, `social`, `combat`, `autoBoss`, `channel`); `bot/village.mjs` giữ hàm phụ làng / hồn kỹ chung với luồng A / B (`villageKit(mapId)` trả `safe`, `inSafeOf`, `leaveSafe`, `VILLAGE_RY`; `skillCast`, `comboHits`), bài cần chúng nhận `vil` ở bảng `STANDALONE`.
- CI (`.github/workflows/check.yml`, chỉ tham khảo) có job `bot-ram`: bài nhanh + bot RAM + lượt nhiều kênh trên mỗi push vào PR. Review đọc kết quả CI (`gh pr checks`, `gh run view <id>` in số ✓ / ✗ / ⚠ từng nhóm và các dòng ✗) thay vì tự chạy bot RAM; lượt PostgreSQL vẫn tự chạy.

## PostgreSQL ở máy
- **Đổi SQL / `db.ts` thì thử thêm với PostgreSQL**, sau lượt bot ở chế độ RAM: `npm run bot:local -- --only <nhóm> --pg`. Công cụ dùng **một PostgreSQL chung cho cả máy** (binary `embedded-postgres` trong `node_modules`, cổng `BOT_PG_PORT` 5433, dữ liệu `BOT_PG_DIR` mặc định `D:/soul-pg-shared`; chưa chạy thì tự bật, đang chạy thì dùng lại), mỗi lượt một database riêng UTF8 (`soulbot_<phiên>_<pid>`, có dấu `COMMENT ON DATABASE`; công cụ chỉ dọn database có dấu đó), bật server **hai lần liên tiếp** (migration phải chạy lại an toàn) rồi chạy bot, xoá database khi xong. Có PostgreSQL cài sẵn thì đặt `BOT_PG_URL`. Xem / tắt instance chung: `npm run bot:local -- --pg-status` / `--pg-stop`.
- **Nhị phân của instance chung nằm ngoài worktree (#1499):** lúc bật, công cụ chép `native` của `@embedded-postgres/<nền tảng>` sang `BOT_PG_DIR/bin-<phiên bản>` (một lần, chép sang thư mục tạm rồi đổi tên; file `.ok` đánh dấu đủ) và chạy `initdb` / `pg_ctl` / `postgres` từ đó, nên worktree bật instance bị dọn thì instance vẫn đủ thư viện / `share` (trước đây hỏng kiểu `could not access file "plpgsql"`, `ECONNRESET`). Đổi phiên bản `embedded-postgres` thì có thư mục `bin-<phiên bản mới>`, thư mục cũ xoá tay được khi instance đã tắt.
- **Phát hiện và tự dọn:** mỗi lượt `--pg` nối thử và chạy một khối plpgsql trước khi tạo database. Instance trả lỗi lạ (thiếu plpgsql, `ECONNRESET`…) hoặc đang chạy bằng nhị phân ngoài `bin-*` (instance cũ do bản công cụ trước bật; chỉ bật lại khi không còn lượt bot khác) thì công cụ in PID + đường dẫn nhị phân (kèm cảnh báo nếu file đã mất), **chỉ tắt khi chắc là của bot:local** (`postmaster.pid` ở `BOT_PG_DIR/data` còn sống, đúng thư mục dữ liệu và cổng, là tiến trình postgres; `pg_ctl stop -m immediate`, không được thì kết thúc đúng PID đó) rồi bật lại bằng nhị phân bền. Cổng do tiến trình khác giữ (PostgreSQL cài sẵn, phiên dùng `BOT_PG_DIR` khác…) thì **không tắt hộ**, chỉ báo PID / nhị phân và dừng với gợi ý.
- `--pg-status` nhận ra instance đang giữ cổng dù do phiên khác bật (PID, nhị phân, còn trên đĩa không, bản bền hay không) và báo `HỎNG (<lỗi>)` thay vì "không chạy"; `--pg-stop` cũng chỉ tắt instance của bot:local. Dò PID theo cổng dùng `lsof` (macOS / Linux) hoặc `netstat` (Windows), thiếu thì bỏ qua phần đó.
- **Đường vòng** khi cổng 5433 đang bị instance không phải của công cụ giữ: `BOT_PG_PORT=57xx BOT_PG_DIR=/tmp/<riêng> npm run bot:local -- --only <nhóm> --pg` (instance riêng, tắt bằng `--pg-stop` với cùng hai biến).
- Người chạy server dev với PostgreSQL: `docker compose up -d` và `cp .env.example server/.env`.
- **Supabase là DB test:** `DATABASE_URL` trỏ Supabase được dùng cho quay ảnh, đo FPS (Q39 ở `docs/quyet-dinh.md`); bot đầy đủ và migration mới vẫn chạy `bot:local`. Prod là PostgreSQL trong cụm K8s, **không bao giờ trỏ**.

## Nhiều phiên song song
`bot:local` tự chọn cổng và giới hạn số lượt. Tự bật tiến trình khác (server dev, Chrome) thì dùng cổng riêng và chỉ tắt đúng PID mình bật, không tắt theo cổng hay theo tên. Chrome chụp ảnh luôn có `--mute-audio` (không phát nhạc khi chạy bot); cổng CDP 9333 đã có người dùng, không tự chiếm.

## Tài khoản test và lệnh GM
- **Tài khoản test**: `npm run seed:test --prefix server -- --name <tên> --preset max|giua-game|moi` (mặc định chạy thử, không nối DB; ghi thật cần `--confirm-db <host>`); **agent không bao giờ trỏ nó vào DB thật**, chỉ thử trên MemoryStore / PostgreSQL cục bộ (`npm run test:seed --prefix server`, `TEST_DATABASE_URL` cho PgStore; bot: `npm run bot:local -- --only testacc --seed-test max --pg`). Hướng dẫn cho chủ repo ở `docs/test-accounts.md`.
- **Lệnh GM**: `/gm …` trong chat, chỉ `accounts.id` trong `ADMIN_ACCOUNTS` (trống = tắt); thử bằng `npm run test:gm --prefix server` và `npm run bot:local -- --only gm --pg`; không bao giờ đặt `ADMIN_ACCOUNTS` cho DB / server chạy bot hoặc đo tải ngoài máy mình. Từ #663: `npm run test:gate --prefix server` (trong `test:unit`) kiểm server giống prod (hook test tắt, GM từ chối), và `--fatal` RAM; bài bot `gm` nằm trong nhóm khói (BOT_PART=smoke) và nhóm 3.
