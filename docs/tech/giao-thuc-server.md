**Message từ client** (đăng ký trong `MapRoom.onCreate`; message chưa đăng ký làm Colyseus ngắt client, nên bỏ message thì sửa client và bot cùng lúc):

| Nhóm | Message |
|---|---|
| Di chuyển, đánh | `input {x, y, s}`, `attack`, `skill {i}`, `boneskill {i}`, `chanthan`, `switch {slot}`, `fusion {op}` (Võ Hồn Dung Hợp Kỹ: `start`, `join`; mục 5.9) |
| Võ hồn | `vohons`, `team {slots}`, `loadout {rowId, skills}`, `unlock {vohon}`, `starup {vohon}` |
| Túi đồ | `bag`, `use {id, vohonId?}`, `pickup`, `discard {id}`, `open {id}`, `absorb {itemId, vohonId}`, `sortbag`, `lock {id}` (khoá / mở khoá), `autosell {cfg}` (bộ lọc tự bán `SellSettings`) |
| Hồn cốt, hồn hạch, trang bị | `equip` / `unequip`, `equipcore` / `unequipcore`, `equipgear {id}` / `unequipgear {slot}` (trang bị hồn sư, mục 5.15), `equipenh {id, charm}` / `equipenhpreview {id}` (cường hóa trang bị hồn sư ở Thợ rèn), `enhance {targetId, materialIds}`, `enhancecore {targetId, materialIds}`, `coreset {id, set, npc}` (Thợ rèn đổi bộ hồn hạch) |
| NPC | `talk {npc}`, `buy {code, qty, npc?}`, `sell {id, qty?, npc?}`, `expand {npc?}`, `buyback {key, npc?}` (`npc`: thương nhân đang mở hộp thoại, thiếu thì thương nhân gần nhất), `quest {op, chain?}` (`chain`: bài khảo hạch hằng ngày), `tong {op, tong?}` (gia nhập / đổi / rời tông môn, mục 5.14), `shardbuy {vohon, qty, npc}` / `shardinfo` (Thương hội đổi mảnh võ hồn, trả tin riêng `shardinfo {n, daily}`, mục 5.7), `looks {looks, npc?}` (đổi ngoại hình ở thợ may; trả tin riêng `looksinfo {n, err?}`, mục 5.11) |
| Bản đồ, kênh | `travel {portal}`, `wp {op, key?}` (truyền tống trận: `list`, `go`, `cancel`), `channels`, `channel {ch}`, `boss` (xin lại tin boss lúc vào phòng) |
| Tự săn | `auto {op, cfg?}` (`on`, `off`, `set` cài đặt `AutoSettings`, `get`; mục 5.13) |
| Xã hội | `chat {text, ch?, to?}` (`ch`: thiếu = bản đồ, `party`, `whisper` với `to` = tên, `world`, `tong`; mục 4 "Kênh chat"), `party {op, name?, sid?}`, `friend {op, name?}` (`list`, `add`, `remove`, `block`, `unblock`; mục 5.9 "Bạn bè"), `arena {op, roomId?}` (`queue`, `cancel`, `top`, `live`, `watch` với `roomId`; trong sân người xem gửi `unwatch`), `resonance` |
| Kiểm thử | `test {op}` (chỉ khi server bật `GAME_TEST=1`) |

Mỗi message: ép kiểu và kẹp giá trị, kiểm tra id có thật và thuộc chính người gửi, kiểm tra trạng thái (gục, hấp thụ, đi cổng, giao chiến, vùng an toàn), hồi chiêu do server đếm; từ chối thì gửi lý do bằng tin `log` tiếng Việt, không ném lỗi. Ép kiểu bằng kiểm `typeof` (`numIn` / `intIn` / `strIn` trong `MapRoom.ts`), không `Number()` / `String()` / so sánh trên giá trị thô (đổi kiểu một object tùy ý có thể ném lỗi). Lỗi bất ngờ còn sót trong handler, hẹn giờ, tick thì `MapRoom.onUncaughtException` chỉ ghi log (giới hạn tần suất), phòng chạy tiếp. Lỗi bất ngờ ngoài mọi phòng (`uncaughtException` / `unhandledRejection` của tiến trình, `index.ts`) thì không chạy tiếp: ghi log kèm stack, lưu người chơi đang online như khi tắt server (rời mọi phòng, chuỗi lưu từng người, hạn `SHUTDOWN_SAVE_MS`), đóng PostgreSQL (`SHUTDOWN_DB_MS`) rồi thoát mã 1 để trình quản lý tiến trình khởi động lại; SIGINT / SIGTERM cũng lưu như vậy rồi thoát mã 0 (chưa lưu xong thì mã 1). Client không gọi được `create` của matchmaker (`index.ts`): phòng bản đồ mới chỉ mở qua `joinOrCreate` khi mọi kênh đầy, sân đấu chỉ do server mở. Matchmake (`joinOrCreate`, `joinById`) giữ chỗ và mở kênh ở bước HTTP, trước khi mở WebSocket, nên `static onAuth` của `MapRoom` kiểm trước: token hợp lệ, tài khoản giữ chưa quá `SEAT_PENDING_MAX` chỗ chưa dùng, bản đồ xin vào có thật và đúng bản đồ đang lưu, đã có hồn sư (sân đấu: chỉ thành viên trận, `seatAllowed`); `onAuth` của phòng vẫn kiểm lại và nạp DB lúc mở WebSocket. Tin client xin lại dữ liệu riêng (`bag`, `vohons`, `quest {op: "get"}`) theo nhịp `ASK_CD`: xin dồn thì gộp thành một lần gửi khi hết nhịp. Trong lúc phần thưởng boss chờ DB xác nhận lượt (`claimBusy`) thì không bán / bỏ / hấp thụ / nộp đồ.

**Bảo mật:** giới hạn đăng nhập sai, số tài khoản mới mỗi IP (`/api/login` tự tạo tài khoản; chỉ đếm lần thật sự tạo, hết lượt thì 429 nhưng tài khoản cũ vẫn vào được; ngưỡng là hằng `SIGNUP_IP_*`, nới khi `GAME_TEST=1`), chat (riêng từng kênh) và lời mời tổ đội ở `server/src/ratelimit.ts` (RAM); khoá IP chuẩn hoá bằng `ipKey` (IPv6 gom theo /64, `::ffff:a.b.c.d` về IPv4), dùng chung cho đăng nhập sai và tạo tài khoản. Deploy sau proxy thì đặt `TRUST_PROXY=1` (thiếu thì mọi người chung IP của proxy, chạm giới hạn tạo tài khoản rất nhanh). Kiểm thử: `npm run test:ratelimit --prefix server`.

**Đăng nhập Google (#612):** ID token của Google Identity Services được `google-auth-library` xác minh ở server (chữ ký, `iss`, `aud` = `GOOGLE_CLIENT_ID`, `exp`, `email_verified`); định danh là `sub`, lưu ở bảng `account_identities` (`UNIQUE(provider, subject)` và `UNIQUE(account_id, provider)`: một Google một tài khoản, một tài khoản tối đa một Google; RLS bật, không policy). Không lưu email / tên / token Google và không ghi chúng vào log. Vé chọn tên ký HMAC (`GOOGLE_TICKET_SECRET`; thiếu thì ngẫu nhiên mỗi lần khởi động, nhiều tiến trình phải đặt chung), chỉ chứa `sub` và hạn 10 phút. Ba route Google dùng chung giới hạn theo IP `ssoCheck` (`ratelimit.ts`); tạo tài khoản còn tính vào giới hạn tạo tài khoản mới. `GOOGLE_CLIENT_ID` là cấu hình công khai (không phải bí mật), trống thì tắt đăng nhập Google. Bộ kiểm giả (credential `test:<sub>[:tên]`) chỉ bật khi `GAME_TEST=1` và `NODE_ENV` khác `production`. Kiểm thử: `npm run test:google --prefix server`, `npm run bot:local -- --only google [--pg]`.
